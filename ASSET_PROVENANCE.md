# Simulation visual provenance

The simulator keeps collision geometry and physical parameters independent from
replaceable art assets.  Every externally sourced model, texture, material,
shader, audio file, or prefab added after this point must record:

- source repository or asset-store URL;
- exact commit, release, or download date;
- original file paths;
- upstream license or written permission reference;
- local modifications and the person who imported it.

## 2026-09-07 visual-fidelity pass

No third-party binary assets were copied in this pass.  The pool tile texture,
lane markings, deck, animated water mesh, lighting, camera response shader, and
gate details are generated by Berkeley AUV code in this repository.

The design was informed by:

- McGill Robotics `auv-sim-unity`, commit
  `69c33dc7abbc7ce7254d030f57a1c7c2d8332f1f`: full pool scenes, distinct
  competition props, configurable underwater cameras, and RGB/depth streams.
  The repository is GPL-3.0 and currently uses an HDRP-oriented asset stack.
- Duke Robotics `cv-simulation`, `main` as inspected on 2026-09-07: randomized
  lighting, gate appearance, camera pose, and visibility for perception data.

Those projects are references, not runtime dependencies.  Their HDRP/older-Unity
materials should not be dropped into this URP project without conversion; an
incompatible shader renders bright magenta in Unity.

The team reports that the upstream teams granted permission to reuse material.
If a future change imports their files, attach the permission record to the team
design drive and add a file-level entry here before merging.
